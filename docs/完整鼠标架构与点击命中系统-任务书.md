## 3. 当前基线与根因

当前实现存在三个断层：

1. `src/client/terminal-session.ts` 启用 `1000 + 1006`，明确关闭 `1002` 和 `1003`；因此只能收到按下/释放和滚轮，不能收到按键拖动轨迹。
2. `terminalMouseDelta()` 只返回滚轮增量，其他鼠标报告统一返回 `null`，随后在 `src/client/surface.ts` 被消费。
3. `Transcript.scrollBy()` 在短页且 `hasMore=true` 时可以发起加载，但没有先脱离 `followLatest`；prepend 后视口仍会回到底部。`finiteViewportLines()` 还会在脱离 follow 后、可见内容不足一页且没有更新内容时重新进入 follow。

因此，选择文本、稳定滚动条和点击控制不能在现有单一滚轮函数上继续堆叠，必须引入协议、手势、布局、命中和选择五个明确层次。

### 4.2 终端协议

最终完整模式进入序列必须具备等价语义：

```text
disable 1000, 1003, 1007
enable 1002, 1004, 1006
```

终端不提供可靠、通用的 `1004` 能力探测；完整模式直接发送 `1004h`，不支持的终端会忽略。退出或切换到原生模式时必须关闭 `1000/1002/1003/1004/1006/1007`。不得启用 `1003`。

备用屏幕和鼠标报告必须拥有独立生命周期：

- `enter()` 只在 Surface 启动时发送一次 `1049h`；最终 `restore()` 只在 Surface 结束时发送一次 `1049l`。
- 新增 `setMouseReporting('full' | 'native')`，运行时切换只写鼠标/焦点私有模式，不得写 `1049h/1049l`、清屏或重建 Surface。
- `full → native → full` 期间必须保持同一个备用屏幕和 viewport，避免重新引入 #147 的闪屏、历史重放和视口跳动。

统一事件：

```ts
interface CellPoint { readonly col: number; readonly row: number }
interface MouseModifiers { readonly shift: boolean; readonly alt: boolean; readonly ctrl: boolean }
type MouseButton = 'left' | 'middle' | 'right' | 'none'

type MouseInput =
  | { readonly kind: 'press'; readonly button: MouseButton; readonly point: CellPoint; readonly modifiers: MouseModifiers }
  | { readonly kind: 'release'; readonly button: MouseButton; readonly point: CellPoint; readonly modifiers: MouseModifiers }
  | { readonly kind: 'drag'; readonly button: MouseButton; readonly point: CellPoint; readonly modifiers: MouseModifiers }
  | { readonly kind: 'wheel'; readonly axis: 'vertical' | 'horizontal'; readonly delta: number; readonly point: CellPoint; readonly modifiers: MouseModifiers }
  | { readonly kind: 'focus'; readonly focused: boolean }
```

约束：

- 对外统一使用零基行列，协议边界负责从 SGR 的一基坐标转换。
- 必须先保存并屏蔽 modifier 位 `4/8/16`，再按无 modifier 的 base code 分类；若原始 `Cb` 含 bit 7（额外按钮）则先安全消费，base `64/65` 是纵向 wheel，`66/67` 是横向 wheel，base 含 bit 5 是 drag/motion，结尾 `m` 是 release，其余 `M` 才是 press。测试必须覆盖带 Shift/Alt/Ctrl 的四种 wheel code，不能用未经屏蔽的 `68/72/80` 等值做精确相等判断。
- 必须保留 Shift/Alt/Ctrl，不再像当前实现一样抹除后只取滚轮位。
- SGR 没有 Cmd/Super modifier 位，设计和测试不得声称能从鼠标报告识别 Cmd。
- protocol 层的 wheel `delta` 表示 `+1/-1` detent；`wheelScrollLines` 和加速只在 controller 层应用。
- 未完成、粘连和畸形序列必须被有限缓冲并安全恢复；不能泄漏成 composer 文本。
- 普通 CSI 键、Bracketed Paste、Kitty 键盘序列和终端尺寸回复不得被误判为鼠标。
- 横向滚轮必须被识别；首版无横向容器时安全消费，不能误判成按钮。
- button 8 及以上的额外按钮首版识别后安全消费，不注册动作。
- `CSI I` 和 `CSI O` 只能分别解析为 FocusIn/FocusOut，不得吞掉其他 CSI。

### 4.3 当前帧命中表

每次完整 TUI frame 生成一份不可变命中快照：

```ts
interface CellRect {
  readonly col: number
  readonly row: number
  readonly width: number
  readonly height: number
}

interface HitRegion {
  readonly id: string
  readonly rect: CellRect
  readonly zIndex: number
  readonly role: 'text' | 'scrollbar' | 'button' | 'option' | 'input' | 'link' | 'passive'
  readonly enabled: boolean
  readonly action: MouseAction
}

type MouseAction =
  | { readonly kind: 'focus'; readonly targetId: string }
  | { readonly kind: 'transcript'; readonly command: string; readonly targetKey?: string }
  | { readonly kind: 'composer'; readonly command: string; readonly logicalOffset?: number }
  | { readonly kind: 'overlay'; readonly command: string; readonly optionId?: string }
  | { readonly kind: 'chrome'; readonly commandId: string }
```

规则：

- 只登记当前可见控件，禁止把完整会话转换为命中节点。
- ID 必须稳定，例如 `transcript:tool:<key>`、`overlay:<id>:option:<id>`；`MouseAction` 必须是可序列化意图，不得包含闭包、Session 对象或 Harness face 引用，统一交给现有 Transcript/TuiActions dispatcher。
- capturing overlay 使用严格高于全部 chrome 的独立 z-band；只要该 overlay 活动，就登记覆盖整个 viewport 的 blocker，而不只是 overlay 矩形。overlay 外的 click/wheel 被消费但不关闭 overlay，overlay 矩形内未命中子控件的空白也被消费，任何事件都不得落到 transcript、composer、examples 或 chrome。
- “更小矩形优先”只允许用于同一非 capturing z-band 的同类候选，不能覆盖 overlay capture。
- BottomAnchoredLayout 和各组件只发布自己坐标空间内的 content-relative 矩形；它们不得把 padding/slice 前的行号宣称为屏幕坐标，鼠标控制器也不得复制 layout 算法猜坐标。
- 命中快照只能在 pi-tui 完成 root padding/slice、overlay clamp、slice 和 composite 后冻结。唯一的 frame finalizer 使用 pi-tui 返回的 post-slice root screen origin 与 overlay screen rect，把局部矩形统一翻译成屏幕坐标；overlay 最终位置来自实际 composite frame，不得复制 `resolveOverlayLayout()`。
- 在提交 2 中一次性扩展精确版本 pi-tui patch：暴露 post-slice root screen origin 以及 overlay 最终 `{row,col,width,height,zOrder,capturing}`；为 Editor 暴露通用 `setCursor`、selection、visual-line map 和 autocomplete selected-index/apply API。后续提交不得反复改同一补丁接口。
- overlay 子区域先以局部坐标登记，再由 frame finalizer 平移。PromptEditor 命中必须包含它自己添加的 gutter、边框、事实行、附件行和 autocomplete，而不是把裸 Editor 坐标直接当屏幕坐标。
- hit-test 目标为 O(可见区域数)；若区域显著增多，再使用按行 bucket，禁止提前引入复杂空间树。

### 4.4 手势状态机

控制器必须显式区分：

```text
idle
pressed(target, origin, time)
selecting(selection target)
dragging-scrollbar(scroll target, grab offset)
edge-scrolling(selection target, direction)
suppressed-after-focus
```

判定：

- 左键按下并在同一格释放：单击。
- 移动到不同单元格：立即转为拖动或文本选择；转化后本次手势不能再触发 click。
- 400ms 内、同一按钮、同一语义目标的第二次点击：双击。
- 400ms 内第三次点击：三击。
- 每次 release 只能分发一个语义事件，不能同时触发 single-click 和 double-click。文本目标按一/二/三击切换 caret/word/line；按钮类目标首次立即执行并在 400ms 内抑制相同重复激活；`focus-then-activate` 目标首次只聚焦、下一击至多执行一次。
- 释放、FocusOut、Session 切换、overlay 替换、模式切换、dispose 和异常关闭都必须结束手势和定时器。
- 不依赖 hover，因为 `1003` 被禁止；仅在 press/drag/release 时提供反馈。
- 右键首版只处理“已有选区时复制”；没有选区时安全消费并提示可用原生模式，不模拟平台上下文菜单。
- 中键不执行粘贴，避免未授权内容进入 composer；原生 middle-click 由原生模式或终端 Shift override 提供。

### 4.5 滚轮路由和合并

顺序固定为：

1. 最上层活动 overlay 的可滚动区域；
2. composer autocomplete；
3. composer 自身的可滚动窗口；
4. 指针位于 transcript 时的 transcript，包括 search 状态；
5. 无命中时安全消费。

若存在 capturing overlay，第 1 步实际为“先由全 viewport blocker 接管，再在 overlay 矩形内寻找滚动子区域”；overlay 不可滚或指针在其外部时直接消费，禁止继续执行第 2—5 步。

要求：

- 同一渲染帧内滚轮增量累加，只发起一次 scroll 操作和一次 render 请求。
- 固定速度限制在设置范围。启用加速时：相邻同方向 detent 间隔不超过 80ms 则 streak 从 1 递增到最多 4，超过 120ms 或方向改变立即重置；有效行数为 `min(12, wheelScrollLines * streak)`，一帧合并后仍以 12 行封顶。
- 滚动和分页统一调用 transcript viewport API，禁止 mouse path 维护第二套 scroll offset。search 模式不得调用当前会为每个 block 执行 `renderBlock()` 的 `ensureSearchIndex()`；搜索索引改为按稳定 block key 从逻辑源文本增量维护，打开搜索、滚轮、滚动条和 resize 都只通过有限 viewport 与虚拟高度索引定位、按需渲染可见块。
- 指针离开局部滚动区后，下一次滚轮必须重新 hit-test。
- 原生模式的目标是恢复 emulator selection；在备用屏幕中不承诺应用内 wheel。原生模式继续提供 transcript focus 后的键盘 PageUp/PageDown/Home/End。

## 5. Transcript 视口和 #151 修复

### 5.1 短页分页

SeekTTY 统一定义 `delta > 0` 为向更早历史移动；SGR wheel-up（Cb 64）产生正 detent。当向更早历史移动、当前 viewport 无法移动、但 `hasMore=true` 时：

1. 先把当前可见起点保存为稳定 `TranscriptCoordinate`；
2. 将 `followLatest` 设为 `false`；
3. 再请求一次 older page；
4. `loadingOlder=true` 时禁止重复请求；
5. prepend 后以原起点为锚，使用新增旧内容向上回填空白；
6. 不得因为 `!hasNewer && visible.length < rows` 自动回到 follow；
7. 只有用户向较新方向实际到达 latest、按 End、或提交新消息时恢复 follow；
8. `hasMore=false` 且不能移动时停止，不产生空转 render。

新增单一 `requestOlderFromStart(anchor)` 路径。`scrollBy`、`scrollToStart`/Home、滚动条轨道、滑块拖动和边缘自动滚动都必须调用它；不能只修 `scrollBy()`。`finiteViewportLines()` 的短页 auto-follow 必须删除，`reachesLatest` 只允许在明确向较新方向滚到实际底部时成立。

### 5.2 虚拟高度索引

为了绘制滚动条而全量调用 `renderBlock()`不可接受。实现一个宽度相关的虚拟高度索引：

- 已访问块保存准确高度；
- 未访问块使用上一次宽度的比例估算或受限默认估算；
- 使用 Fenwick tree、segment tree 或等价增量结构；准确/估算高度的单块更新和前缀查询都必须为 O(log n)，流式 tail 更新不得线性改写“所有后续前缀和”。
- 支持坐标到估算 offset、offset 到 block coordinate 的 O(log n) 查询；鼠标路径不得复用会遍历所有 turn block 的 `navigateTurn()`。
- 普通 snapshot reconcile 按稳定 block key 保留索引，只更新新增、删除或高度变化的块；Session 全量切换可以 O(n) 重建索引结构，但仍不得调用所有块的 `renderBlock()`/Markdown。
- resize 后立即保留锚点，索引按需修正，不能同步重排完整历史；
- 测试和 UI 必须把未知高度标记为估算，不把它宣传为完整历史的精确比例。

## 6. 常驻内部滚动条

### 6.1 视觉和几何

- 默认在 transcript 最右列保留一列低对比度轨道。
- 禁止淡入、淡出、闪烁和滚轮触发的颜色动画。
- 有溢出时绘制滑块；无溢出时绘制全高禁用滑块。
- `hasMore=true` 时顶部使用不同端帽表示仍有未加载历史。
- `loadingOlder=true` 时仅改变端帽符号，不启动动画定时器。
- terminal 宽度小于 12 列时允许隐藏，content width 至少保持 1。
- 滚动条列永远不属于文本选择内容。
- 滚动条上线后删除 transcript 首尾内容行上的 older/newer marker；`hasMore`、`loadingOlder` 和 newer 状态只由轨道端帽表达，不能保留两套闪动提示。

### 6.2 交互

- 单击滑块开始拖动，保留抓取点相对滑块顶部的 offset。
- 单击轨道跳到当前已加载/估算范围的对应位置。
- 在顶部且 `hasMore=true` 时请求下一页，并维持拖动锚点。
- 完整历史总量未知时，不允许一次拖动跳进尚未加载的虚假绝对位置。
- Home/End、滚轮和拖动后滑块必须由同一个 viewport snapshot 推导，不能单独保存位置。

## 7. 文本选择和复制

### 7.1 稳定逻辑坐标

屏幕行列只用于命中，持久选区必须保存逻辑锚点：

```ts
interface SelectionAnchor {
  readonly surface: 'transcript' | 'composer'
  readonly ownerKey: string
  readonly textOffset: number
  readonly affinity: 'before' | 'after'
}

interface TextSelection {
  readonly anchor: SelectionAnchor
  readonly focus: SelectionAnchor
  readonly granularity: 'character' | 'word' | 'line'
}
```

`textOffset` 是 owner logical text 的 UTF-16 index；grapheme 在选择和 cell 映射时保持原子性，宽度计算必须与 pi-tui `visibleWidth` 的规则一致。一个选区的两个 anchor 必须属于同一 surface，禁止 transcript 与 composer 混合选区。

Transcript 每条可见行需附带从终端 cell 到 owner logical text offset 的映射。映射必须：

- 跳过 ANSI、OSC 8、光标标记和滚动条；
- 把一个 grapheme 当作不可拆分单位；
- 正确处理宽字符、组合字符和 emoji；
- 标记 soft wrap 与真实换行；
- 标记合成 UI 字符，例如行号、折叠提示和分页提示是否可复制；
- 在宽度改变后重新把逻辑锚点投影到可见 cell，而不是清空选区。

### 7.2 选择行为

- 拖动：字符粒度。
- 双击：使用 `Intl.Segmenter` 的 word granularity；无 word segment 时选择一个 grapheme。
- 三击：选择完整逻辑行，不包含滚动条或外部 chrome。
- 支持从后向前选择、跨块、跨页和跨 viewport。
- 拖动到 transcript 顶/底行进入边缘自动滚动；50ms 单一定时器，速度按距边缘单元格数分级并封顶。
- 自动滚到顶部后通过统一分页路径加载 older；加载期间保持手势和原锚点。
- 鼠标在终端外释放导致 release 丢失时，FocusOut 或下一次非拖动输入必须安全终止手势。
- 流式更新和旧历史 prepend 不得改变已选文本的 ownerKey/textOffset。
- owner 被 Session 切换或内容替换删除时清除选区，不允许错误复制其他 Session 文本。
- search 状态继续使用同一 transcript viewport API；必须删除或绕过鼠标/滚动/resize 路径上的全量 `ensureSearchIndex()` 渲染，保留全历史搜索语义时只能增量索引逻辑源文本，不能为建立索引渲染所有 Markdown block。图片本体、额外鼠标按钮和首版未定义的合成控件点击只消费、不动作，图片 caption/alt text 按普通文本选择。

### 7.3 复制规范

- 默认 `copyOnSelect=true`：鼠标释放后写入现有 `writeClipboard()`。
- 复制成功后保留高亮，直到新选择、Escape、Session 切换或显式 clear。
- 右键已有选区再次复制。
- 不重载 Ctrl+C。新增 `copySelection` 键位，默认 `Ctrl+Shift+C`，实现时必须通过 `keyBindingsIssue()` 和各终端按键协议测试；不支持该组合的终端仍可依赖 copy-on-select 或自定义键位。
- 软换行拼接，真实换行保留；不得 `.trim()`。
- 去除 ANSI、OSC、鼠标提示、滚动条、分页端帽和不可复制的合成 chrome。
- 代码缩进、空行、CJK 和 emoji 必须字节级验证。
- 剪贴板失败只显示非阻塞 warning，不清除选区。
- 高亮通过反转/覆盖已经生成的可见 viewport cell 完成，禁止为了高亮再次 `renderBlock()` owner；鼠标选择帧必须保持 `lastFullLinesCopied === 0`。

## 8. 点击功能矩阵

### 8.1 Transcript

| 目标 | 单击 | 双击/三击 | 拖动 |
| --- | --- | --- | --- |
| 普通文本 | 聚焦 transcript、建立 caret anchor | 选词/选行 | 选择文本 |
| 工具卡标题/折叠提示 | 聚焦并切换展开状态 | 不重复触发 | 从文本区开始才选择 |
| 空会话示例 | 第一次聚焦，下一击或 Enter 提交且至多一次 | 双击等价于“聚焦后提交一次” | 不提交 |
| scrollbar older end-cap | 请求一页 | 不重复请求 | 开始选择时不触发分页按钮 |
| scrollbar thumb | 开始拖动 | 同单击 | 调整 viewport |
| scrollbar track | 跳转 | 同单击 | 转为 thumb drag |

工具卡和示例动作必须调用现有 Transcript/TuiActions 路径，不复制业务逻辑。

### 8.2 Composer

- 单击编辑区：聚焦并把 cursor 放到对应逻辑位置。
- 拖动：建立 composer 选区。
- 双击/三击：选词/选逻辑行。
- 输入、Backspace/Delete、粘贴和提交必须先按标准编辑器语义替换/清除选区。
- 自动补全 option：第一次单击移动选中项，下一击或 Enter 执行一次；双击不能重复提交。
- 当前附件是一个合并的 pending line，不虚构 chip 或鼠标删除按钮；该行只可聚焦，删除继续使用现有 `/attachments` 或键盘路径。

若 pi-tui Editor 缺少 cursor/selection API，精确版本 patch 只增加通用的逻辑 cursor、selection 和 visual-line mapping 接口；SeekTTY 不得访问其私有字段。

### 8.3 Overlay

- capturing overlay 活动期间，以全 viewport blocker 捕获 click/wheel；overlay 外部只消费、不关闭，overlay 矩形内的空白也阻止穿透。
- option 单击只移动焦点；第二次点击或双击执行普通动作。
- overlay 内滚轮只滚动该 overlay。
- 可取消普通 overlay 可通过明确的关闭目标退出；不得默认点击外部即关闭。
- danger/permission confirmation 的鼠标单击只能改变焦点，执行始终需要 Enter；首版不新增独立 confirm widget，也不允许用第二次点击执行危险确认。
- overlay 被替换时废弃旧 frame ID，旧 release 不能作用于新 overlay。

### 8.4 Context/status chrome

Context/status 不能从已经 compact 的最终字符串反向猜子串坐标；应先把当前实际绘制的 facts 重构为带稳定语义 ID 的 token，compact 后只给实际保留下来的、且已有键盘等价动作的 token 注册点击：

- composer rule 中实际保留的 model/mode → 打开各自已有 picker；
- status 中实际保留的 permission/detail → 打开或聚焦已有 control/detail；
- context 中的其余现有 fact 只有在当前确有键盘动作时才可点击，否则保持纯文本。

不得为了完成矩阵新增当前 chrome 没有绘制的 Session/workspace token，纯文本事实也不得伪装成按钮。任何新鼠标入口必须有键盘路径和帮助说明。

## 9. 链接与终端所有权

- 完整模式不为 OSC 8 文本注册应用 hit region，也不从鼠标报告启动浏览器；普通点击只执行 caret/选择语义。
- SGR 无 Cmd/Super 位，因此完整模式不承诺 Cmd+click。终端原生 OSC 8 打开使用 emulator 的 Shift override（若支持）或 `mouseMode=native`。
- 应用逻辑链接只有在它不是同一 OSC 8 目标、且存在现有安全动作时才登记；外部 URL 首版不由完整模式打开。
- 实机测试断言 SeekTTY 的 URL launch 调用次数为零，避免应用与终端双重所有权；不对 emulator 是否仍处理捕获模式点击作跨终端承诺。
- 模型输出中的转义序列在进入命中解析前必须经过现有安全转义路径，不能伪造 hit region。

## 10. 焦点恢复和危险操作保护

- 解析 `1004` FocusIn/FocusOut，并记录本进程是否至少观察到一组 FocusOut→FocusIn；终端不报告该协议时进入明确的安全降级态。
- FocusIn 后 250ms 内的第一组 press/release 只恢复 TUI 焦点，不执行 option、button、link 或 submit。
- FocusOut 立即结束选择 drag、scrollbar drag、click count 和 edge-scroll timer。
- danger/permission 鼠标永不执行，只能聚焦后按 Enter。delete、submit 等敏感动作只有在本进程已观察到可靠 FocusOut→FocusIn 后才允许鼠标执行，并仍受 250ms 首击保护；未观察到焦点协议时，鼠标只聚焦并提示使用 Enter。这样不支持 `1004` 的终端不会把 Alt-Tab 返回后的第一击当作执行。
- 点击开始时绑定目标 frame generation；release 时 generation 不一致则丢弃动作，防止 UI 更新后的 click-through。

## 12. 性能预算和可观测性

结构性预算：

- 禁止出现 `1003h`。
- pointer drag 和 wheel 每帧最多触发一个 render request。
- hit-test 不访问不可见 TranscriptBlock。
- selection highlight 每帧最多处理 viewport 行数。
- 100k 行 cached frame 继续满足现有 `blocksVisited`、`componentRenders`、`linesEscaped` 和 `lastFullLinesCopied` 上界。
- scrollbar height index 更新不得调用完整 transcript render。
- height-index 单块 update/query 为 O(log n)；流式 tail update 不得改写线性数量的 prefix entry。
- mouse selection/scrollbar 帧必须保持 `lastFullLinesCopied === 0`。
- 鼠标 controller dispose 后 active timers、pending frame callback、drag state 均为零。

性能测试新增计数：

- parsed mouse events；
- coalesced wheel events；
- hit regions and hit-test candidates；
- selection cells projected；
- edge-scroll timers；
- mouse-triggered render requests；
- height-index exact/estimated entries。

时间指标只作为实机记录，不使用容易受 CI 抖动影响的硬毫秒断言；自动测试以结构性操作上界为准。

- 未直接采纳“删除 chrome 点击”的建议：本任务要求完整点击架构，因此改为语义 token 渲染，只给 compact 后仍可见且有键盘等价动作的 token 建 hit region，不解析最终字符串，也不虚构控件。
- 保留 wheel acceleration，但补充了可测试的时间阈值、streak 和单帧上限。

### 18.2 冻结条件

第二轮使用新的 Cursor CLI `cursor-grok-4.6-xhigh` 非 fast 只读会话，结论仍为 `ACCEPT WITH REQUIRED CHANGES`。Codex 已对照当前源码复核并写回全部成立项：
