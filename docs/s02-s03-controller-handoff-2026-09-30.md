## Published sources and boundaries

Inspected the installed unmodified `@deepseek-ai/*@0.2.0-rc.2` declaration/generated-descriptor artifacts in the read-only source dependency graph. Tests use the actual exported `TYPERT_REMOTE` descriptor and strict codecs. Source locations below come from those descriptors. The provided official git-tree snapshot independently identifies the source paths at the target SHA.

- Session archive/restore/pin: `@deepseek-ai/dsh-api-workspace-controller/remote`, `lib/typert.remote-client.{js,d.ts}` and `lib/types/types.d.ts`. Descriptor source: [`packages/api/workspace-controller/src/index.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/api/workspace-controller/src/index.ts), archive L155, unarchive L165, pin L175, unpin L185. Requests are `{sessionId}`; receipts carry complete `archivedSessionIds` or `pinnedSessionIds`. `stopActivity:true` requests stops but **does not await completion**.
- Stop: `@deepseek-ai/dsh-api-session-controller/remote`, `session/cancel`; descriptor source [`packages/api/session-controller/src/index.ts:457`](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/api/session-controller/src/index.ts#L457). `{accepted:true}` is admission, not idle. Controller separately observes `running:false` in the current complete Host generation; it never archives after failed/unknown stop, timeout, cancellation, reset, disconnect or unknown running state.
- All other running activity: `workspace/session-active` and published `SessionActivity` in workspace-controller/types. After own-turn cancellation and idle, plain archive still lets Host refuse active descendants/jobs/schedules. There is no asserted success for those stops and no client-built stop-all API.
- Composition: `TypertLocalRegistry.get` and `InvocationDescriptor` in `@deepseek-ai/dsh-typert-protocol`; Host registry in `@deepseek-ai/dsh-typert-registry`. `publishedSessionManagementMethods` requires a live direct descriptor **and** mounted receiver method. Client descriptor installation, an npm package, or a withdrawn `hasSeen` endpoint alone is not availability. Registry absence is unknown. SRC-only receivers without a confirmed published descriptor stay unavailable in this conservative adapter.
- Plan: [`packages/plan/plan-mode/src/types.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/plan/plan-mode/src/types.ts) defines Host `plan:{active,pending}`; installed `lib/index.js` registers `/plan [off|message]` and `exit_plan_mode({plan:string})`. Its review question owns complete Markdown `detail` and `plan-review` intent. `/plan` is already inherited by dynamic Host command discovery; there is no separate plan-file/artifact read Remote to invent. Todo projection is the official whole `todos` list or null. Plan text comes only from recorded tool arguments; mode/todos come only from Host projection values.
- Deliveries: [`packages/deliverables/tool-present/src/types.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/deliverables/tool-present/src/types.ts), `deliverables/presented:{turn,callId,files:[{path,description?}]}`. Preserve original seq/index/path. A recorded delivery declaration does not prove current file existence.
- Review: [`packages/deliverables/workspace-changes/src/types.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/deliverables/workspace-changes/src/types.ts). Persisted `workspace/changes` contains only `turn`; `workspaceChanges.summary(sessionId,seq)` and `.diff(sessionId,seq,index,signal)` are actual Host service methods. The Web plugin additionally serves authenticated `api/changes.summary`/`api/changes.diff` HTTP routes; those are not terminal Typert methods. This worker provides the service-shape adapter and controller port; E must route that service through its actual existing authenticated bridge. Undefined means disposed/unrecorded/unavailable, not an empty successful Review. Comparisons validate record identity and refuse unknown kinds.
- Files: [`packages/api/workspace-files/src/types.ts`](https://github.com/deepseek-ai/deepseek-harness/blob/639ed015397290b3745d163aafe02ffee4aa3f84/packages/api/workspace-files/src/types.ts), installed generated `workspaceFiles/read(sessionId,path,{offset,limit},signal)`. Reads require Host-world absolute paths; relative paths resolve only from explicit canonical Host Session cwd, with POSIX/Windows selection independent of client platform. Pages are bounded at 200 lines and a changed `version` requires restart from page one. No `fs.readFile`, client `cwd`/HOME, symlink fallback, or read to build cards.
- Results: native Session `tool/result.data.message` has **flat** `content`/`isError` fields. PTC `tool/ptc-dispatch` carries its own flat content/error. No obsolete `type:tool-result` block unwrap or mutation of B journal. Unknown/malformed blocks and future `artifact/*` data retain generic JSON.
- URL presentation: `@deepseek-ai/dsh-tools/presentation`, official `WebFetchResultView.url` and `WebSearchResultView.sources`. Decorated `event.view` is optional Host render intent; no link is extracted from arbitrary output strings. Missing/unsafe opener/copy actions are disabled or fail visibly.

## Minimal E wiring

All module APIs are exported from the source files; no package export or dependency change is required for internal integration.

1. Construct one `SessionBrowserController` per TUI/runtime. `source.getSnapshot()` combines the existing Session catalog (including archived summaries), native Workspace archive/pin/order baseline, and connection generation. `ready` means current complete Session **and** Workspace baselines under an established connection; a mutation's loading flag must not invalidate its own baseline. Reuse existing reliable root/lineage projection before handing rows to the browser. Do not apply old `listSessions()` active-only filtering first.
2. Bind `remote` to the five real native Remote methods with their native `RemoteResult` receipts. Do not cast the Workspace facade's `Promise<void>` to a successful receipt. `methods()` is the current Host composition check above, delivered through the existing Host bridge; clear/recompute on connection reset and plugin composition changes. `open` uses the existing Session open path so draft/viewport ownership stays unchanged.
3. In the existing `/sessions` branch, route exactly `active|all|archived` (or blank) to `sessionBrowserCommand(browser,args,host.overlays)`. Preserve existing arbitrary `/sessions <search phrase>` behavior for other args. Existing `/archive` and context archive call `browser.mutate('archive',id,signal)` inside their confirmation/progress flow; restore/pin/unpin route similarly. No `stopActivity:true`. Only announce success after controller resolution; cancellation during an already-dispatched unary has an explicitly unknown outcome, so refresh rather than automatically retry.
4. Construct one `ArtifactViewController` with a source over B's current event journal and native Host projection cells. Include original optional `ToolEventView` decoration when available; do not re-normalize, wrap results, or fetch history independently. `hostWorkspacePath` is the Host summary cwd. `hasMoreHistory` keeps loaded-window coverage honest. Wire source invalidation to Session selection, projected values, event/window changes, connection loss and generation replacement.
5. Add `/plans` (to avoid shadowing inherited native `/plan`), `/review`, and a recorded-results/attachments entry under existing `/trajectory`/`/files` menus:

   ```ts
   await artifactViewCommand(artifactController, 'plan', host.overlays)
   await artifactViewCommand(artifactController, 'review', host.overlays)
   await artifactViewCommand(artifactController, 'trajectory', host.overlays)
   await artifactViewCommand(artifactController, 'files', host.overlays)
   ```

   These calls are complete overlay flows tested with the same `OverlayPrompts` contract. Keep existing produced-file groups, request details, pending-review questions and live running calls. Populate dynamic help/catalog with the chosen new terminal names.
6. `files` is the real composed `workspaceFiles.read`, never `readProducedFile`'s client-local implementation. Attach only when Host descriptor/service is confirmed; propagate real native failure code/message. `review` is `mountedArtifactReviewReader(ctx.get('workspaceChanges'))` through the existing authenticated Host bridge; no fake gateway namespace. Check actual service composition each generation. If absent or the bridge is not attached, retain durable announcements and present the reason. `links.copy` delegates to existing terminal clipboard; `links.open` delegates to the existing platform opener after a gesture. No model request or tool execution occurs.
7. On runtime disposal call `artifactController.dispose()`. It releases its source subscription and aborts all current reads. Keep the same controller while merely closing/reopening overlays to retain per-Session selection. No file-watch subscription is created. Overlay refresh reads current authoritative rows; the menu also refuses a Session/generation change before dispatch.
