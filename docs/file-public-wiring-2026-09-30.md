# Public Files intake (official dsh 0.2.0-rc.2)

`/attach-file [path]` uploads a bounded local file through official Agent-scoped fileUploads/upload and stages its opaque receipt. Text, mp3 and mp4 all use the same saved-file handle semantics; the UI does not infer native model modalities from names. Existing `/attach` image intake is retained. `/attachments` exposes file details/remove and a confirmed clear of selected images/files; clear/remove changes only local draft selection. The composer displays selected filenames/counts.

`/file-references [query]` reads the official path-only Host discovery service. File and directory choices insert ordinary JSON-quoted @path text, copy the path, or request Host external-open after consent. Discovery never uploads or recursively reads a directory. It is independently available when Files upload is unsupported.

The management factory confirms an exact ordinary live root Agent and an actual AttachmentStore saveFile override, refusing the abstract images-only store. Per-operation ports use the exact published descriptor/parameter/result codecs and original Gateway; no upload route, receipt storage or Host cleanup method is introduced. Stable Agent, storage and upload service identities govern draft ownership; transient UI selection does not mint a new Host generation. WeakMap lifecycle tokens avoid retaining discarded Agents. A returned parent keeps its unsent receipt draft; another Agent does not inherit it. Disconnect/reset/Host owner replacement invalidate local selections and late results.

Retained prompt schema/types now accept the actual official `{type:'file',receiptId}` variant. The existing native Session prompt lifecycle preserves the RPC request ID and queue/steer mode through the terminal dispatcher to official session/prompt. A confirmed acceptance clears only captured receipt/image selections; a refusal leaves them available. New uploads arriving during a prompt remain selected. Continuable child Sessions reject ordinary-Agent receipts before either prompt dispatch.

Admission limits are explicit terminal UI budgets (8 MiB/file, 16 MiB/draft, 8 files), not claims about Host/model limits. Official Files storage itself publishes no file admission limit. Upload reads remain bounded and no raw bytes/path are added to prompt content. Cancellation after dispatch can leave Harness-owned saved bytes or receipts; rc.2 has no receipt revoke endpoint. Profile restart does not persist opaque file receipts as local image paths. Independent review of `190c601` confirmed that cancellation ignored the late receipt without retry, but the progress page closed silently: the earlier statement that a warning was already visible was incorrect. The follow-up now shows an explicit warning that this file was not added to the draft and, if upload began, Host may have saved it; cancellation does not revoke upload or automatically retry. It makes no deletion/rollback claim.

No real keys, model requests, user history, accounts or external browsers were used.
