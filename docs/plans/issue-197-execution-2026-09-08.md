## 已实现

- 输出批次确认直接更新候选 Set / key 索引，不再在 acknowledge 中扫描历史。重复确认同一批次无效。
- 账本区分完整源码提交与已交付物理行数。取消保留部分交付证据；再次出现修订时有来源更正，不把物理行数假装成完整源码覆盖。
- 思考与正文混合节点按 AssistantBlock 来源投影，稳定正文可以在 settled 前提交。精确 token 相同的投影复用；第一来源单元不再因后续正文变化而重复提交。
- 顶层围栏代码每次最多准备 128 个完整源码行，再按最多 256 个物理行输出。每个代码流有独立 GrammarState；只高亮本批新增行，未完成行使用 preview。主题/延迟语法加载重建状态，settled/取消释放状态；无法维持语法状态或高亮报错时保留纯文本正文。
- 删除、隐藏、换序、重新出现和来源块缩减追加来源提示。回放仍追加当前权威历史。用户折叠不冒充源码删除。
- 普通控制输出成功后废弃旧 anchor；协议控制显式标明不改布局。输出成功才发布 tailRow 几何，待交付帧不提前替换 hit map；旧代次或尺寸不符的结果不能发布当前命中区域。
- 不确定部分写失败后停止提交，不重发正文；尝试关闭同步更新/恢复协议，失败仍保持失败状态。
- native Markdown 使用当前 pi renderer 的选择投影去掉展示填充，保留原有代码空格。历史 Canvas 用背景擦除代替追加全宽空格，普通 full Canvas 不变。适配器限于 pi-tui 0.73.1。
- 历史加载只以官方 `hasMore` 判断完成，不再因一页没有增加可见节点而提早退出。仍支持取消和 Session 变更退出。
- 外部回显探针改为有界 onData 标记解析，每轮 75 个原始样本。Windows 界面验收的设置观察改用目录事件触发读取，避免高频轮询原子替换目标。

## 明确保留的成本与下一步

1. 官方 Session.subscribe 没有可靠 changedKeys / revision 契约，旧 snapshot 的 store 仍可能是实时 reader。snapshot 投影、精确 token 比较、来源顺序核对、候选索引仍随历史量增长；新增来源核对就在 update 中，不能从性能报告中排除。
2. 保守 Markdown 边界仍不支持通用容器增量：复杂列表、表格、引用、HTML、链接定义和长未闭合语法留在尾部。顶层代码以外的大节点仍可能一次准备很多行；单个巨长源码行也不是 128 行批次能限制的。不能宣称所有恢复准备已严格有界。
3. 部分物理交付不是逐源码行映射。取消后允许带更正标记重新输出权威片段；并不承诺任意位置取消后无重复地续写那个片段。
4. native 正文当前以文字标签代替图片，此路径不直接发送 Kitty 图片。不能把文本 xterm 测试当成图片协议验收。
5. xterm 断言证明源空格与擦除空白不同，不能替代 UU/真实终端剪贴板。UU 横竖屏、键盘开关、回看与复制仍需人工复测；菜单滚轮问题继续作为观察项。
6. 性能三方基线、固定历史增长回复、超长行、复杂语法、最大停顿逐项归因及所有组合交互仍不是本轮测试的完整覆盖。包内阶段不能仅因现有测试通过就称为全部验收完成。

后续优先围绕实际失败 fixture 扩展：共享 pi Markdown 的解析/间隔上下文、来源范围映射、复杂大节点准备。不要把本轮保守退路永久冻结为设计；也不要为去掉这些成本臆造 Harness API。#197 仍需可靠增量接口、全部结构/完整性/性能和人工门槛、包内默认切换后才可关闭。
