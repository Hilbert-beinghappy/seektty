# S01 / S04 / S08 module handoff

These independent modules target the **published dsh 0.2.0-rc.2** descriptor. They are not connected to public actions, Settings, Provider management, or composer state in this commit. Importing them into the existing client makes them part of the production bundle; the production build alone does not demonstrate these new user flows. E owns that integration and its final-package acceptance.

## Verified contracts

The installed official `dsh-client-file-upload/remote` descriptor exposes `fileUploads.upload(agentId, { data, name? }, signal?)`. Its value is `{ receiptId, file }`. `dsh-api-session-controller/types` accepts `{ type: 'file', receiptId }` in `session.prompt`. Receipt authority belongs to the receiving Agent; an attachment id is not interchangeable with a receipt. There is no public delete-upload method. Clearing, removing or abandoning a draft only removes its local selection; cancellation cannot promise to roll back Host storage after upload admission.

The official `fileReferences.list(agentId, query, signal?)` returns `{ path, kind: 'file' | 'directory' }`. Directory candidates are path references, never recursively uploaded. `session.openWorkspacePath({ path }, signal?)` provides the confirmed external opener for binary, unknown and spreadsheet formats as well as text. Resolve relative paths against the active Host workspace before calling it; remote Host paths must not be read from the client filesystem.

`dsh-llm/types` declares that durable file blocks become saved-file handle text in model requests. Audio and video can be selected as verbatim files; this is not a claim of native audio/video inference. Existing normalized image intake remains the image path.

The official `session.modelCatalog()` drops input modalities and capacity metadata in rc.2. It does not expose a `resolveModel` Remote. `llm.discoverModels(settingsNs, request, signal?)` can return `inputModalities`, `contextWindow`, and `maxTokens`; only results already obtained through the existing Provider flow should be supplied as discovery evidence. Do not issue credential-bearing discovery just to fill the model information overlay.

The optional official account descriptor exposes `getState`, `getBalance(client)`, `startSignIn(client, callbackOrigin, 'desktop')`, `cancelSignIn(attemptId)`, `hasRunningAccountTasks`, and `signOut(client)`. They return flat `{ ok, value/error }` Remote results. Account operations contain no credential payloads. Stored credential presence is not server-validated login. API-key configuration remains a separate Harness capability.

## Minimal integration

- Create `FileAttachmentController(remote, sessionId, filesCapability, budget)` per ordinary Session. `filesCapability` must come from the current Harness Files composition, not from a filename, model modality, or presence of the global upload descriptor alone. Budgets are explicit client admission limits, not invented Host limits. Use workspace-resolved local paths with `addPath`; use `references` for Host paths. Append `promptParts()` to the existing prompt content and clear only after confirmed prompt acceptance. Keep the existing image parts and limits unchanged. Render draft and cold durable `FileAttachmentRef` values through `fileAttachmentLines`; open paths only after confirmation. The existing exported-file index/open flow supplies durable path resolution; these modules do not invent an attachment-id-to-path mapping.
- Create `ModelInformationController(remote)`, refresh on catalog invalidation, and call `info(currentSelection)` for the overlay. Keep Session selection under Harness ownership. Feed real discovery results through `discoveredModelEvidence(provider, result)` and `setEvidence`; explicitly authored metadata uses source `manual`. Unknown metadata stays unknown. `modelImageAdmission` denies images for declared text-only models; unknown allows the existing image intake but returns `support: 'unknown'`, which the caller must show as uncertainty rather than supported. Audio/video receipts do not enter this image gate. `usageInformationLines` keeps official and auxiliary counters separate and preserves missing metrics as unknown.
- Show the account entry only when `AccountHandoffController.available` is true for mounted descriptor methods. Use authoritative route provenance with `accountRouteLabel`; do not classify a provider by its display name. Refresh safe state when entering or after account invalidation. Call `startSignIn` with the browser-accessible origin of the **existing official Host HTTP callback service**, including an SSH forwarded origin if appropriate. A websocket URL or invented callback server is insufficient. Show/copy `loginUrl`; browser opening uses the existing confirmed opener. The controller never starts a server, exchanges tokens, or stores credentials.
- Explicit login cancellation calls `cancelSignIn()`, including when a start request has not yet returned. The controller will cancel that exact late attempt. Aborting UI observation, timing out, disconnecting or disposing alone does not claim to cancel the official Host login attempt. `lateCancellationError` must be surfaced if a deferred cancel fails; refresh official state afterward. Logout uses `signOut(confirmRunningTasks)` with the existing confirmation overlay; refusing, timing out or cancelling before dispatch never calls official signOut. The Host owns task cancellation and credential removal.
- Call `reconnect` with the new Remote (and Session/Files capability for attachments) when connection ownership changes; it fences pending work and clears connection-specific metadata/receipts. Call `dispose` when the owning view/session closes. Returned state never authorizes side effects after cancellation. Already-dispatched Host commands may still commit despite a carrier timeout; re-read Host state before claiming their outcome.

## Validation scope

Tests use isolated temporary files, mocked exact-shape Remote results and one loopback HTTP fixture. They exercise budgets, pending reservations, missing capability, Remote refusal, assembly faults, cancellation, deadlines, late results, reconnect fencing, file-open consent, text-only/unknown metadata, account login cancellation, task-aware logout and balance provenance. No real account, credential, login/logout or remote upload is used. Final public wiring and final packaged Host acceptance remain E's responsibility.

Observed on macOS with Node 24.20.0: typecheck passed; 184 test files passed with 1620 tests passed and 1 skipped; production build and 36-entry pack check passed. The unmodified official rc.2 Host (278 exact-version dsh packages) passed isolated candidate install, boot, remove and reinstall, including worker/module/launcher checks. The candidate contains the existing connected client; that lifecycle pass does not validate public entry points for these unconnected modules. Generated lib was restored before the final full test run and is not committed here. Logs are local `.artifacts/s01-s04-s08-{focused,tests,typecheck,build,pack-check,stock}.log`.
