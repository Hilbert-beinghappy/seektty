## Deliberate terminal compatibility and safe boundaries

The new optional terminal field is `seektty-behavior.workProcessDisplay`. It uses the **published semantics**, not another Host `ui-chat` service or a new Remote API. Absent/null/unknown values resolve to `terminal-default` (UI fallback label only), retaining current toolCards/showReasoning/output/diff preferences without writes. No mode is inserted into `DEFAULT_TUI_BEHAVIOR`. A user selecting one of four modes explicitly opts into its process containers; those containers do not force leaf tool output or full reasoning open. `normal`/`expanded` aliases apply only to this new field, never to old `toolCards:'expanded'`. Terminal budgets still apply, including Verbose; this differs from an unlimited Web layout.

`WorkProcessTurnEvidence` is a narrow structural selection of official projection facts. Supply status/end reason from the owning Turn; spec from native TurnProcessSpec; hasInterleavedInput from native presentation. Unknown/missing/bad owner or boundaries retain content. Native node kinds/anchor/step/groupPart and known registered membership are required to hide a process part; extension nodes with unconfirmed membership stay visible. Do not derive these from status text, regex tool names, Session lineage or guesses. Unknown group.closed also retains the group. These conservative fallback guards are stronger than the browser seat's assumptions about a fully initialized store.

`workProcessTurnPresentation().foldable` means **can fold this whole completed Turn** in the terminal, whereas the browser seat's per-node `foldable` also describes readiness for its live node controller. It is not a claim of identical intermediate state. Caller must also use native `hasExternalProcess || spec.inlineReasoning` and no interleaved input before enabling a Turn disclosure button; empty processes get no fake toggle. There is no duration/activity summary synthesis in this module. Consume native group summary/counts and official end data when available; show a truthful unavailable reason for a missing projection.

## Precise minimal E wiring

1. `src/protocol.ts`: add an optional normalized `workProcessDisplay?: 'compact' | 'standard' | 'detailed' | 'verbose'` on `TuiBehaviorSettings`; do not add a default. Host schema `src/host/management.ts` BehaviorSettingsSchema registers `workProcessDisplay: z.union(['compact','standard','detailed','verbose','normal','expanded']).loose()` with no `.default`. Existing `src/host/settings/behavior.ts` already consumes that schema. Add the current four choices plus **unset/terminal default** in the behavior Settings form; legacy aliases are accepted saved values, never offered choices.
2. `src/client/behavior.ts` normalizeBehavior reads `const processMode = normalizeWorkProcessMode(record.workProcessDisplay)` and conditionally spreads `...(processMode === undefined ? {} : { workProcessDisplay: processMode })`. Unknown schema/raw values fall back to the existing terminal defaults and are not persisted or repaired. On each authoritative Host settings update, `resolveWorkProcessDisplay(normalized.workProcessDisplay, normalized)` supplies policy plus four unchanged leaf preferences. Use the original behavior normalizer to bound budgets first. No writes on initial load, aliases, reconnect or normalization.
3. Add a **new independent action** for process-mode switching (e.g. tools process / command-palette action), preserving existing `tools display`/`toolsDisplay` three-state cycle and `reasoning` key behavior. Register a distinct key action in protocol/keymap and existing dispatcher; users may bind it through existing keyBindings. No new key binding is assumed by this module. The action runs `cycleWorkProcessMode(currentField, direction)` (forward/backward, wraparound; no value -> Compact/Verbose respectively), then re-describes the authoritative behavior document and confirms the actual field descriptor exists. Pass true only for a registered field, false for absent and undefined for undiscovered; the request planner refuses the latter two.
4. Persistence remains the **existing native** `settings.mutate`. Example after user selection:

   ```ts
   const request = workProcessSettingsMutation(document, nextMode, fieldAvailable)
   const accepted = await management.settings.mutate(request.namespace, request.ops, request.expectedRevision)
   applyBehavior(behaviorFromSettings(accepted))
   ```

   The planner sets exactly `[workProcessDisplay]`, or unsets it for `terminal-default`, and preserves CAS revision. Do not rewrite the whole settings object or store local preferences. On error/disconnect/unknown result, retain the last accepted mode and display that actual failure; re-read on reconnect. Revision conflict refreshes the document and asks for a fresh explicit choice; no blind retry. Serializing the action avoids two simultaneous key presses treating a still-unaccepted mode as current. No adapter `signal` is invented for this Settings unary call.
5. `src/client/transcript.ts`: thread policy as a presentation parameter/cache identity; existing undefined-policy path remains unchanged. Feed already projected groups to `workProcessGroupPresentation(policy, turnEvidence, group.data.closed, groupLocalOpen, disclosure)`. Its header/body/outer visibility, running-detail allowance and opening edge inform terminal rows and existing view scroll state. Group/Turn disclosure is local per-instance UI state, not durable Session state. Reuse native immutable group members/parts. Do not equate groups to individual tool cards or implement a second event normalizer. Before hiding a node/part, call `workProcessNodeHidden`; render final response and independent input/status. Mixed final assistant nodes must retain the full answer if no authoritative part split exists. For reasoning previews call `workProcessReasoningPreview(policy, running, expanded, nonemptySummary)`; full reasoning continues using existing local behavior.
6. Preserve source nodes and existing search/copy/export contracts while changing visible rows. Hidden matches must reveal group and owning Turn via the existing disclosure path; include mode/disclosure in cache invalidation so stale compact rows cannot survive switches. E must wire group header hit regions/focus/accessibility, viewport restoration and current scope invalidation. Native groups/spec absent -> content remains visible with the truthful missing-evidence message; mode label alone must not be accepted as equivalent grouped functionality.
